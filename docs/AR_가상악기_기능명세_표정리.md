# 실시간 AR 가상 악기 기능 명세서 표 정리

## 명세 요약

| 항목 | 명세 요약 |
| --- | --- |
| 목적 | 실시간 카메라 영상 위의 가상 악기를 실제 채의 움직임으로 연주하고 사운드·시각 피드백을 제공한다. |
| 개발 플랫폼 | Unity(C#) 기반으로 개발한다. |
| 동작 환경 | 고정 설치한 카메라, 추적 가능 범위 안의 사용자, 실제 연주 채, 모니터 출력. 채 추적과 타격 판정은 깊이를 포함한 3차원 좌표 기반으로 수행한다. 카메라는 필요에 따라 추가할 수 있으며, 수량과 배치는 깊이 확보 방식·가림·추적 정확도에 따라 결정한다. |
| 최종 범위 | 영상·AR, 채 추적·타격, 두 채 동시 연주, 강도·효과, 보정·복구, 악기 전환. |
| 문서 읽는 법 | 1쪽 전체 기능 목록 → 2~9쪽 기능별 상세 표 → 10쪽 성능·시험 → 11쪽 시나리오·데이터 → 12쪽 범위·결정·완료 조건. |
| 정리 원칙 | 원문 SRS v1.0을 바탕으로 3차원 좌표 기반 추적·타격 판정과 필요에 따른 카메라 확장을 반영한다. 일정·인력·특정 추적 기술 선택 제안은 포함하지 않는다. |

### 공통 공간 좌표와 카메라 구성

- 채 끝점, 이동 벡터, 악기 및 타격 영역은 동일한 Unity 월드 좌표계의 3차원 값으로 표현한다. 위치 단위는 미터, 속도 단위는 미터/초로 통일하고 공통 원점·축 방향·스케일은 보정으로 정한다.
- 화면 좌표는 영상 합성·커서·UI 표시를 위한 투영 결과로 사용한다. 타격은 깊이를 포함한 월드 좌표와 3차원 타격 영역을 기준으로 판정한다.
- 카메라 수는 고정하지 않는다. 선택한 깊이 확보 방식으로 요구 정확도를 충족하는 구성을 사용하며, 필요하면 카메라를 추가한다. 일반 영상의 화면 좌표에 임의의 고정 깊이를 넣는 방식은 3차원 추적으로 간주하지 않는다.
- 여러 카메라를 사용하는 경우 카메라별 식별·타임스탬프, 관측 시각 정렬, 카메라 간 공간 보정을 적용하여 같은 채의 관측을 하나의 월드 좌표로 통합한다. 출력 영상의 기준 카메라를 지정한다.
- 카메라 수·배치·깊이 확보 방식이 변경되면 관련 보정을 갱신한다. 유효한 3차원 위치를 확보하지 못한 채는 추적 실패로 처리하고 타격 판정에서 제외한다.

## 기능별 상세 명세

### FR-001 카메라 실시간 입력 | P0 · 핵심

| 항목 | 명세 내용 |
| --- | --- |
| 설명 | 시스템은 연결된 카메라로부터 사용자의 모습을 실시간으로 촬영하고 영상 프레임을 수신할 수 있어야 한다. |
| 상세 요구사항 | 1. 시스템은 구성된 카메라를 각각 인식하고 영상 입력을 시작할 수 있어야 한다.<br>2. 입력된 영상은 카메라 ID와 타임스탬프를 가진 연속적인 프레임 형태로 처리되어야 한다.<br>3. 카메라에서 전달받은 영상과 사용 가능한 깊이 정보는 채 인식·3차원 위치 추정에 전달하고, 기준 카메라 영상은 AR 합성에 제공해야 한다.<br>4. 카메라 연결이 끊어진 경우 해당 카메라 입력을 중단하고 오류 상태를 전달해야 하며, 남은 입력으로 유효한 3차원 위치를 얻지 못하면 해당 채의 타격 판정을 중단해야 한다.<br>5. 필요에 따라 카메라를 추가 구성할 수 있어야 하며, 복수 카메라 사용 시 관측 시각을 정렬하여 위치 추정에 사용해야 한다. |
| 입력 | 카메라별 영상 프레임, 카메라 ID, 타임스탬프, 선택한 방식의 깊이 추정 입력 |
| 출력 | 카메라별 실시간 영상 데이터 및 시각 정렬된 추적 입력 |
| 검증 기준 | 구성된 카메라의 영상이 연속 수신되고 추적·화면 모듈에 전달되어야 한다. 복수 카메라 구성에서는 시각 정렬을 확인하고, 연결 해제 시 위치 유효성에 따라 판정이 유지되거나 중단되어야 한다. |

### FR-002 거울 모드 및 화면 출력 | P0 · 핵심

| 항목 | 명세 내용 |
| --- | --- |
| 설명 | 시스템은 촬영된 영상을 모니터에 실시간으로 출력하고 사용자가 거울을 보는 것처럼 자신의 움직임을 확인할 수 있도록 해야 한다. |
| 상세 요구사항 | 1. 시스템은 기준 카메라 영상을 실시간으로 화면에 출력해야 한다.<br>2. 사용자는 영상의 좌우 반전 여부를 선택할 수 있어야 한다.<br>3. 거울 모드를 활성화하면 카메라 영상을 수평으로 반전해야 한다.<br>4. 거울 모드 변경 시 채와 악기의 월드 좌표를 화면에 투영한 결과도 동일하게 반전해야 한다. 표시 반전으로 추적·타격 판정용 월드 좌표가 변경되어서는 안 된다.<br>5. 화면 출력 중 영상의 비율이 임의로 왜곡되지 않아야 한다. |
| 입력 | 실시간 카메라 영상, 거울 모드 설정 |
| 출력 | 일반 또는 좌우 반전된 실시간 영상 |
| 검증 기준 | 거울 모드를 변경하더라도 화면에 표시되는 채의 위치와 타격 판정 위치가 일치해야 한다. |

### FR-003 가상 악기 생성 및 위치 설정 | P0 · 핵심

| 항목 | 명세 내용 |
| --- | --- |
| 설명 | 시스템은 가상 악기의 3D 모델을 공통 월드 좌표계에 배치하고 카메라 영상 위에 표시할 수 있어야 한다. |
| 상세 요구사항 | 1. 시스템은 선택된 악기의 3D 모델을 생성해야 한다.<br>2. 가상 악기는 지정된 3차원 위치와 자세로 배치되어야 한다.<br>3. 악기의 위치·회전·크기를 설정할 수 있어야 한다.<br>4. 가상 악기는 하나 이상의 3차원 타격 영역으로 구성될 수 있어야 한다.<br>5. 각 타격 영역은 고유한 식별 정보와 대응 사운드 정보를 가져야 한다.<br>6. 사용자가 움직이더라도 공간에 고정 배치된 악기의 월드 좌표는 유지되어야 한다. |
| 입력 | 악기 3D 모델, 월드 위치, 회전, 크기 및 타격 영역 배치 정보 |
| 출력 | 공통 월드 좌표계에 배치되고 화면에 투영된 가상 악기 |
| 검증 기준 | 악기가 설정된 위치·자세·크기로 표시되고, 각 3차원 타격 영역이 채 추적과 동일한 월드 좌표계에 배치되어야 한다. |

### FR-004 영상과 AR 악기 합성 | P0 · 핵심

| 항목 | 명세 내용 |
| --- | --- |
| 설명 | 시스템은 카메라 영상과 가상의 악기를 하나의 화면으로 합성하여 실시간으로 출력해야 한다. |
| 상세 요구사항 | 1. 기준 카메라 영상 위에 가상 악기가 표시되어야 한다.<br>2. 가상 악기의 위치·자세·크기는 설정된 월드 좌표 기준을 따라야 한다.<br>3. 기준 카메라의 보정 정보로 월드 좌표를 화면에 투영하여 실제 채와 가상 악기가 공간적으로 대응해야 한다.<br>4. 사용자와 채의 움직임이 갱신되는 동안 AR 악기의 표시가 유지되어야 한다.<br>5. 입력 해상도·기준 카메라·카메라 배치가 변경되면 관련 보정 정보와 화면 투영을 갱신해야 한다. |
| 입력 | 기준 카메라 영상, 카메라 보정 정보, 월드 좌표 기반 가상 악기 렌더링 정보 |
| 출력 | AR 악기가 합성된 실시간 영상 |
| 검증 기준 | 영상과 가상 악기가 동일한 화면에 표시되고, 움직이는 채의 위치와 가상 악기의 타격 영역이 시각적으로 일치해야 한다. |

### FR-005 채 인식 | P0 · 핵심

| 항목 | 명세 내용 |
| --- | --- |
| 설명 | 시스템은 카메라 영상에서 사용자가 들고 있는 실제 연주 채를 감지하고 식별할 수 있어야 한다. |
| 상세 요구사항 | 1. 시스템은 영상 내 연주 채의 존재 여부를 판별해야 한다.<br>2. 채가 검출되면 관측 카메라 ID와 위치 정보를 반환해야 한다.<br>3. 복수의 채가 검출되면 각 채를 구분하여 식별해야 한다.<br>4. 연속된 영상에서 동일한 채의 식별 정보를 유지하고, 복수 카메라 사용 시 같은 채의 관측을 공통 채 ID로 대응시켜야 한다.<br>5. 채가 인식되지 않거나 검출 신뢰도가 부족하면 해당 채를 추적 실패 상태로 처리해야 한다. |
| 입력 | 카메라 영상 프레임 |
| 출력 | 카메라별 채 검출 결과, 공통 채 식별 ID, 영상 내 검출 위치 |
| 검증 기준 | 지정된 연주 환경에서 채를 인식하고, 두 개의 채가 존재하는 경우 서로 구분하여 식별할 수 있어야 한다. |

### FR-006 채 끝점 트래킹 | P0 · 핵심

| 항목 | 명세 내용 |
| --- | --- |
| 설명 | 시스템은 인식된 연주 채의 끝부분을 연속적으로 추적하고 깊이를 포함한 실시간 3차원 월드 좌표를 계산해야 한다. |
| 상세 요구사항 | 1. 검출된 채에서 실제 타격에 사용되는 끝점의 3차원 월드 좌표(x, y, z)를 계산해야 한다.<br>2. 유효한 관측 시점마다 위치와 타임스탬프를 갱신하고, 복수 카메라 관측은 시각 정렬·공간 보정 후 통합해야 한다.<br>3. 각 채의 끝점 위치를 독립적으로 관리해야 한다.<br>4. 채 끝점의 움직임에 따른 3차원 좌표 변화를 기록해야 한다.<br>5. 가림·미검출·깊이 추정 실패로 유효한 3차원 위치를 얻지 못하면 추적 실패 상태로 갱신해야 한다.<br>6. 오래되거나 깊이 유효성이 확보되지 않은 좌표를 새로운 타격 판정에 사용해서는 안 된다. |
| 입력 | 카메라별 채 검출 결과, 시각 정렬된 관측·깊이 추정 입력, 카메라 보정 정보 |
| 출력 | 채 ID별 3차원 월드 끝점 좌표, 관측 시각, 추적 상태 및 신뢰도 |
| 검증 기준 | 채의 좌우·상하·앞뒤 이동에 따라 x·y·z가 갱신되고, 깊이를 포함한 위치 오차가 합의된 허용 범위 이내여야 한다. 유효한 3차원 위치가 없으면 타격이 발생하지 않아야 한다. |

### FR-007 이동 방향 및 속도 측정 | P0 · 핵심

| 항목 | 명세 내용 |
| --- | --- |
| 설명 | 시스템은 채 끝점의 연속적인 좌표 변화를 활용하여 채의 이동 방향과 속도를 계산해야 한다. |

### 타격 이벤트 공통 필드

`stick_id` · `instrument_id` · `zone_id` · `timestamp` · `velocity` · `intensity` · `position`. `position`은 3차원 월드 좌표, `velocity`는 월드 속도 벡터(미터/초)를 의미한다. 오디오와 시각 효과 모듈이 공통으로 사용한다.

### 주요 의존 관계

카메라 구성·공간 보정·관측 시각 정렬 → 채 인식·관측 대응 → 3차원 월드 끝점 추정 → 방향·속도 → 3차원 타격 → 중복 제거 → 공통 이벤트 → 오디오·시각 효과. 기준 카메라 영상과 동일한 보정 정보로 월드 악기·채 위치를 화면에 투영하여 AR 합성한다. 동시 타격은 판정·이벤트·오디오·효과 전체에 적용한다.
