# Unity 프로젝트 협업 안내

## 환경과 시작 범위

- 프로젝트 경로: `unity/ARInstruments`
- 에디터: Unity 6 `6000.0.25f1` (이 PC에 설치된 버전)
- 시작 방식: 설치된 에디터에 포함된 공식 **3D URP** 템플릿(`com.unity.template.3d-cross-platform-17.0.11.tgz`)의 Assets·Packages·ProjectSettings로 구성합니다. URP 설정과 기본 카메라·조명이 있는 시작 씬을 유지하며, 템플릿의 Library 캐시와 튜토리얼은 복사하지 않습니다.
- 개정 명세의 **3차원 월드 좌표 기반 채 추적·타격 판정**을 기준으로 합니다. 카메라는 깊이 확보 방식·가림·추적 정확도에 따라 필요 수량을 구성하고 추가할 수 있습니다. 현재 AR Foundation 등 추적·깊이 확보용 패키지는 추가하지 않았으며, 적용 기술과 카메라 구성은 후속 설계에서 정합니다.
- 초기화 범위: 프로젝트 설정, 역할별 폴더, 모듈별 어셈블리, 기존 규약의 공통 데이터와 이벤트 버스. 기능 구현은 포함하지 않습니다.

## 열기와 검증 상태

Unity Hub의 **Add → Add project from disk**에서 `unity/ARInstruments`를 추가하고 위 버전으로 엽니다. 시작 씬은 `Assets/Shared/Scenes/Main.unity`이며 빌드 씬 목록에도 등록되어 있습니다. 기본 씬에는 아직 카메라 입력·연주 기능이 연결되어 있지 않습니다.

설치된 공식 템플릿 파일을 사용해 초기화했습니다. 2026.11.09 사용자 확인 기준, Unity Hub 라이선스 활성화 후 프로젝트 열기와 기본 씬의 Play 모드 실행을 오류 없이 완료했습니다. 이 확인은 현재 초기 프로젝트의 기본 실행에 대한 것으로, 카메라 입력·3차원 추적·타격·오디오 기능은 구현 후 별도로 검증합니다. 다른 팀원도 첫 실행에서 패키지 복원과 임포트를 완료하고 Console 및 Play 모드를 확인합니다.

## 소유 폴더와 명세 연결

| 폴더 | 담당 | 작업 범위 |
| --- | --- | --- |
| `Assets/Tracking` | A | 카메라별 입력·관측 시각 정렬(FR-001), 채 검출·카메라 간 ID 대응·3차원 끝점 추정·월드 속도(FR-005~007), 공간 보정·깊이 유효성·실패 감지(FR-014~015) |
| `Assets/Presentation` | B | 기준 카메라 영상·거울 모드·월드 악기 배치·화면 투영·합성(FR-002~004), 시각 효과(FR-013), 보정·실패 안내 UI(FR-014~015), 악기 전환 UI(FR-016) |
| `Assets/Performance` | C | 월드 좌표와 3차원 타격 영역의 경로 교차 판정·중복 방지(FR-008~009), 음원·동시 연주·강도(FR-010~012), 악기 전환 시 판정 상태 초기화(FR-016) |

각 담당 폴더 안의 `Scripts`, `Prefabs`, `Scenes`를 사용합니다. B의 `Materials`, `UI`, `VFX`, C의 `Audio`, 공통 `Shared/Settings`, 모델별 `Models/Janggu`, `Models/Buk`도 준비합니다.

## 모듈 간 계약

`docs/event_bus_architecture_data_structures_ko.md`의 `MalletState`, `HitEvent`, `GameEventBus`를 `Shared/Scripts`에 그대로 옮깁니다. 명세서의 더 넓은 이벤트 요구사항과 현재 계약 간 차이는 후속 설계에서 합의하며, 초기화 단계에서는 필드를 임의로 추가하지 않습니다.

각 모듈의 `.asmdef`는 `ARInstruments.Shared`만 참조합니다. Tracking, Presentation, Performance 사이의 직접 참조는 추가하지 않고, 모듈 간 통신은 `GameEventBus`를 사용합니다. UI 등 새 패키지가 필요한 경우 해당 모듈에 그 패키지의 어셈블리 참조를 추가합니다.

- A: `OnMalletsTracked`와 `OnTrackingLost` 발행. 충돌·타격 판정은 C가 담당합니다.
- C: `OnMalletsTracked` 구독, `OnValidHit` 발행. 오디오도 `OnValidHit`를 구독합니다.
- B: 추적·추적 실패·유효 타격 이벤트를 구독하여 화면과 효과를 갱신합니다.
- Unity 오브젝트를 다루는 이벤트는 Unity 메인 스레드에서 발행합니다. 외부 CV 작업 스레드의 결과는 메인 스레드로 전달한 뒤 발행합니다.
- 구독은 `OnEnable`에서 추가하고 `OnDisable`에서 해제합니다. 기본 Domain Reload 설정을 유지합니다.
- `MalletState.Position`과 `HitEvent.HitPosition`은 **동일한 Unity 월드 좌표계의 3차원 위치(미터)**를 사용하고, `MalletState.Velocity`는 해당 좌표계의 **3차원 속도(미터/초)**를 사용합니다. 공통 원점·축 방향·스케일은 보정으로 정합니다. 데이터 구조의 필드와 이벤트 시그니처는 유지합니다.
- A는 관측을 보정·통합하여 유효한 깊이를 포함한 월드 좌표를 발행하고, C는 같은 월드 좌표계의 3차원 Collider와 이전·현재 위치 사이의 경로 교차를 검사합니다. 유효한 3차원 위치를 얻지 못한 채는 추적 실패로 처리하여 타격에 사용하지 않습니다.
- B는 기준 카메라 보정 정보로 월드 좌표를 화면에 투영합니다. 화면 정규화 좌표는 표시용으로 사용하며, 거울 모드에서는 영상과 투영 결과를 함께 반전합니다. 표시 반전으로 추적·타격 판정용 월드 좌표를 변경하지 않습니다.

## 카메라 구성과 공간 보정

- 카메라 수는 고정하지 않으며, 요구 정확도와 가림 대응에 따라 늘릴 수 있습니다. 선택한 깊이 확보 방식으로 3차원 위치를 얻을 수 있는 구성을 정합니다. 일반 영상의 화면 좌표에 임의의 고정 깊이를 넣는 방식은 사용하지 않습니다.
- 복수 카메라 사용 시 A는 카메라별 ID·타임스탬프, 관측 시각 정렬, 동일한 채의 관측 대응과 공통 월드 좌표 변환을 관리합니다. B는 영상 합성에 사용할 기준 카메라를 사용합니다.
- 카메라 내부 파라미터·왜곡, 카메라별 월드 위치·자세, 공통 원점·축·스케일과 관측 시각 정렬 정보를 보정합니다. A·B·C가 같은 보정 기준을 사용하도록 공통 설정을 관리하고 모듈 간 상태 전달은 이벤트 버스를 사용합니다. 추가 이벤트가 필요하면 기존 규약을 팀에서 합의하여 확장합니다.
- 카메라 추가·배치·기준 카메라 변경 시 관련 보정과 화면 투영을 갱신하고, 유효성이 복원될 때까지 영향을 받는 채의 판정을 중단합니다. 카메라 일부가 끊겨도 남은 입력으로 유효한 3차원 위치를 확보할 수 있다면 추적을 유지할 수 있습니다.
- 검증 시 x·y·z 이동, 알려진 공간 위치와의 오차, 화면상 겹침만 있고 깊이가 다른 비타격, 관측 시각 불일치·깊이 추정 실패 시 판정 중단, 카메라 추가 후 재보정을 확인합니다. 카메라 구성과 3차원 위치·투영 오차의 허용치는 후속 설계에서 확정합니다.

## 모델과 Git 관리

루트 `assets/`는 모델 제작 담당자의 로컬 전용 작업 폴더입니다. `.gitignore`의 `/assets/` 규칙으로 하위 파일 전체를 Git 공유 대상에서 제외하며, 저장소를 새로 받으면 이 폴더는 포함되지 않습니다. `assets/janggu`, `assets/buk`의 `.blend`, `.glb`, 미리보기 원본은 로컬에서 수정·보관합니다.

팀에서 사용할 런타임용 모델은 `unity/ARInstruments/Assets/Models`로 별도 내보내 공유합니다. 이 Unity 폴더와 `.meta`는 Git 관리 대상입니다. Unity 기본 임포터로 사용할 `.fbx`로 내보내거나 glTF 임포터를 팀에서 선택한 뒤 가져옵니다. 자동 모델 복사나 임포터 패키지 설치는 수행하지 않습니다.

Unity의 Version Control Mode는 **Visible Meta Files**, Asset Serialization은 **Force Text**를 사용합니다. `Assets`의 `.meta`, `Packages`와 `ProjectSettings`를 함께 공유하고 `Library`, `Temp`, `Logs`, `UserSettings`는 제외합니다. 비어 있는 리소스 폴더에는 `.gitkeep`을 두어 Git에서도 구조를 유지합니다.

저장소 루트 이름은 현재 `TEAM6` 그대로 사용합니다. 별도의 `AR_TEAM6` 폴더를 중첩 생성하지 않습니다.
