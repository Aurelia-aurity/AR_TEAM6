# 마커 기반 단일 악기 배치·감시·재정렬 계약

개정: 2026.11.17. 목표 설계 계약이며 런타임 구현은 별도 작업이다. 아래 타입·이벤트 이름은 제안명이며 구현 시 공유 계약으로 확정한다. 기존 MalletState·HitEvent 필드는 변경하지 않는다.

## 1. 책임과 배치 기준

A는 촬영·원본 Texture 수명·채의 3차원 추적·복수 카메라 통합을 담당한다. B는 마커 검출·위치 추정·기준 카메라 배치용 보정·감시·재정렬 진행·악기 선택과 표시를 담당한다. C는 타격 영역·음원·판정 중단과 재개를 담당한다. 모듈 간 통신은 Shared 이벤트 버스로만 수행한다.

마커는 같은 물리적 위치에 계속 고정한다. 동시에 악기 하나만 활성화하며 마커 ID와 악기 종류는 독립적이다. 마커 기준의 월드 배치와 악기의 상대 조정값을 저장한다. 자동 재정렬은 카메라의 변환을 갱신하고 사용자 배치를 유지한다. 악기 교체 시 공통 배치 기준을 유지하고 새 악기의 기본 보정값을 적용한다. 악기별 사용자 조정값 재사용 정책은 구현 전 확정한다.

B는 검출기 좌표를 Unity 월드 좌표(미터)로 변환한다. A의 채·C의 영역도 동일한 보정 버전을 사용한다. 입력 회전·상하 보정과 사용자 거울 반전을 분리한다. 마커 위치 추정은 채 깊이 추정을 대신하지 않는다. 해상도·렌즈·기준 카메라 변경으로 보정이 무효화되면 필요한 보정을 다시 수행한다. 복수 카메라 전체 정합은 A와 함께 검증한다.

## 2. 영상 분석 계약 — 기존 카메라 계약 보강

CameraFrameData의 기존 필드를 유지하고 세션 내 단조 증가하는 FrameSequence 추가를 제안한다. CameraId + SessionId + FrameSequence로 분석 프레임을 식별한다. ReceivedAtMs는 수신 시각이며 센서 촬영 시각이 아니다.

A 소유 Texture는 변경 가능한 참조다. B는 이를 수정·정지·해제하거나 같은 카메라를 별도로 열지 않는다. B는 분석 프레임을 별도 버퍼에 확보하고 그 복사본의 수명을 관리한다. 복사본은 특정 프레임 내용을 유지하며 식별 정보와 함께 묶는다. 이벤트 콜백에서 장시간 검출을 수행하지 않는다. 작업 스레드에서 Unity Texture API를 임의로 호출하지 않는다. 복사·GPU 읽기 비용도 측정한다.

동시 분석 수·대기열을 제한하고 오래된 요청을 누적하지 않는다. 세션 종료·보정 변경·작업 취소 후 도착한 결과는 폐기한다. 표시 경로는 검출 완료를 기다리지 않는다. Unity 오브젝트 관련 이벤트는 메인 스레드에서 전달한다.

## 3. 데이터 계약

| 제안 데이터 | 필수 의미 |
| --- | --- |
| MarkerDefinition | 사전·ID·검은 외곽 기준 실측 한 변 길이 |
| MarkerObservation | 카메라·세션·프레임·분석 보정 버전, 관측 시각, 마커 위치·회전·품질·유효성 |
| CalibrationSnapshot | 보정 버전, 카메라·세션·해상도·영상 방향, 내부 파라미터·왜곡 모델·카메라↔월드 변환·유효성 |
| InstrumentDefinition | InstrumentTypeId, 모델·영역·음원 설정 식별자, 기본 상대 위치·회전·크기 |
| PlayContextSnapshot | ContextVersion, 보정 버전, 마커 기준 월드 배치, 선택 악기·사용자 상대 조정·크기·운영 상태 |
| ContextApplyResult | ContextVersion, 응답 모듈 A/C, 성공·실패·오류 코드 |

MarkerObservation은 기본적으로 B 내부 데이터다. A/C에는 확정 보정·배치·상태를 전달한다. 공유 스냅샷은 발행 후 변경하지 않으며 배열 등 참조 데이터도 변경되지 않도록 소유권을 정한다. InstrumentTypeId는 현재 HitEvent.InstrumentId(타격 영역 ID)와 구분한다.

ContextVersion은 보정·배치·선택 악기 변경 시 증가한다. 실행 시작 시 상태를 초기화하고 이전 실행 작업을 취소한다. 오래된 완료 응답·검출·추적 결과는 적용하지 않는다.

## 4. 감시와 운영 상태

| 상태 | 동작 | 새 타격 |
| --- | --- | --- |
| Unplaced | 마커 인식 안내 | 중단 |
| Placing | 미리보기·조정·확정 | 중단 |
| Active | 확정 위치 유지·저빈도 마커 확인 | 허용 |
| Realigning | 안정 관측 확보·보정 준비 | 중단 |
| Applying | A/C 동일 버전 적용 대기 | 중단 |
| RecoveryRequired | 오류·재시도·수동 재배치 안내 | 중단 |

마커 검출됨·가려짐·불안정은 운영 상태와 별도로 관리한다. 일시 가림은 기존 배치를 유지하며 이동을 의미하지 않는다. 이동 확인 후 가림은 복구 대기를 유지한다. 장기 미검출 정책은 별도 확정한다. 가려진 동안의 이동은 재등장 전까지 감지하지 못할 수 있다.

직전 관측뿐 아니라 마지막 확정 기준과 비교하여 느린 누적 이동을 감지한다. 품질·위치·각도·여러 관측의 지속성으로 판단하고 단일 오차는 배치에 적용하지 않는다. 재정렬 시작과 안정화 완료 기준을 구분한다. 상대 관측만으로 마커 자체 이동과 카메라 이동을 구분하지 못하므로 고정 마커를 전제로 한다.

## 5. 이벤트와 적용 순서

| 제안 이벤트 | 방향 | 의미 |
| --- | --- | --- |
| OnPlayStateChanged | B → A/C | 상태와 ContextVersion 통지 |
| OnPlayContextProposed | B → A/C | 새 불변 컨텍스트 적용 요청 |
| OnContextApplyCompleted | A/C → B | 같은 버전 적용 결과 |
| OnPlayContextActivated | B → A/C | 준비된 버전 활성화 |

새 이벤트는 event Action<T>와 발행 메서드로 제공한다. 구독 해제·재활성화 시 최신 상태/확정 컨텍스트 조회를 제공한다. 저장된 Active를 읽더라도 새 소비자가 준비되지 않았으면 판정을 재개하지 않고 적용 준비 절차를 거친다. 비활성화·필수 모듈 이탈은 준비 상태를 무효화한다.

1. B가 새 버전과 비연주 상태를 동기 발행하고 C는 새 타격을 중단한다.
2. B가 보정·배치·악기 설정을 준비해 제안한다.
3. A는 새 변환을 적용하고 이전 위치·속도 이력과 비동기 결과를 정리한다. C는 영역·음원·타격 잠금 상태를 갱신한다.
4. A/C가 같은 버전의 성공을 응답하면 B가 활성화한다. A의 성공은 보정 적용 완료이며 두 채 모두 검출됨을 의미하지 않는다.
5. C는 새 버전의 유효한 추적 이력이 확보된 뒤 판정한다. 초기 샘플을 이전 좌표와 연결하여 타격을 만들지 않는다.

실패·시간 초과는 RecoveryRequired로 전환하며 오래된 응답으로 재개하지 않는다. 전환 중 이전 음원의 잔향 유지 여부는 별도 정책으로 정하되 새 타격·잘못된 효과 발생은 금지한다.

## 6. 버전 있는 추적·타격 전달

기존 MalletState·HitEvent 필드는 유지한다. ContextVersion과 기존 데이터를 묶는 전달 형식 및 이벤트를 추가하여 실제 판정·오디오·효과는 활성 버전만 처리한다. 구형 이벤트는 호환용으로 유지할 수 있으나 동일 처리기가 두 경로를 동시에 소비해 중복 타격을 만들면 안 된다. 기존 수신 시각만으로 적용 버전을 추정하지 않는다. A/B/C가 함께 전환할 통합 작업이며 현재 구현되었다고 간주하지 않는다.

## 7. 검증과 미정 값

정지 흔들림, 사람·채만 움직임, 느린 누적 카메라 이동, 가림 중 이동 후 재등장, 사용자 조정 보존, 악기 교체, 입력 재시작, 오래된 분석/추적/응답, 적용 실패·시간 초과·모듈 재활성화, 두 채 동시 타격을 검증한다. 실제 영상·채·판정 영역의 공간 오차와 감시 부하를 측정한다.

라이브러리·사전·ID·실측 크기, 분석 해상도·감시 주기·품질 기준·변화 임계값·확인 횟수·안정화 시간·장기 미검출 정책·적용 제한 시간·허용 오차·감지 지연은 실측 후 확정한다. 저빈도 감시는 이동 직후부터 감지까지 공백이 있으므로 즉시 감지나 그 구간의 무오류를 보장하지 않는다.
