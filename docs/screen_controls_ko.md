# 화면 하단 컨트롤 바

`feat/screen-ui`의 `ScreenControlBar`는 Play 모드에서 UI를 생성한다. `Shared/Scenes/Main.unity`와 `Presentation/Prefabs/CameraDisplay.prefab`에 연결되어 있어 카메라·장구 미리보기 씬에서도 표시된다. 미리보기의 기존 디버그 화면은 그대로 유지한다.

- 1280×720 기준 높이 64의 하단 바. 버튼 높이 40, 실행 88 / 악기 128 / 모드 144 너비. 화면 크기에 따라 스케일되며 safe area를 따른다.
- 왼쪽: 실행/정지 → 악기 선택. 오른쪽: 현재 사용자/관리자 모드. 중앙은 향후 버튼을 위한 여백이다.
- 악기 메뉴는 위로 펼쳐지고 위에서부터 장구, 북, 징, 꽹과리 순서다. 선택하거나 메뉴 바깥을 누르면 닫힌다.
- 관리자 전용 도구와 채 커서 표시 정책은 아직 구현하지 않는다. 모드 상태만 전환하며 `ModeChanged`로 후속 화면을 연결할 수 있다.
- `koreanFont`를 Inspector에서 지정할 수 있다. 미지정 시 OS 한글 글꼴을 찾는다. 배포 기기에 한글 글꼴이 없다면 라이선스가 확보된 한글 폰트를 프로젝트에 포함하고 지정해야 한다.

## 실제 기능 연결

현재 main에는 공통 연주 실행 제어기가 없다. UI 선택 자체가 카메라·추적·음원 시작이나 악기 모델 교체를 수행하지 않는다. 연결되지 않은 실행 버튼은 안내 문구를 표시하며 실행된 것으로 표시하지 않는다.

같은 Unity 메인 스레드에서 `ScreenControlBar.State`를 사용한다.

1. 제어기는 `RunRequested(int requestId, bool requestedRunning)`를 구독한다. 구독/해제는 수명에 맞게 수행한다.
2. 실제 시작 또는 정지가 완료되면 `CompleteRunRequest(requestId, true)`를 호출한다. 실패하면 `CompleteRunRequest(requestId, false, error)`를 호출한다.
3. 대기 중 버튼은 중복 요청을 막는다. 시작 성공 후에만 정지로 바뀐다. 정지 실패 시 정지 버튼을 유지한다. 기본 15초 후 응답 대기를 종료하며, 이전 요청에 대한 늦은 응답은 무시한다.
4. 외부 종료·실패나 초기 실제 상태는 `ReportRunning(bool)`으로 동기화한다. UI 타임아웃은 실제 작업 취소가 아니므로 제어기는 요청 취소/늦은 실제 완료를 처리하고 실제 상태를 다시 보고해야 한다.
5. `InstrumentChanged(ScreenInstrument)`와 `ModeChanged(ScreenMode)`를 구독해 후속 기능을 연결한다. 초기값은 장구와 사용자 모드다. 악기 선택은 UI 선택 상태이며 실제 악기 준비 완료를 의미하지 않는다.

모듈 간 직접 참조를 추가하지 말고, 실제 제어기 통합 시 팀에서 합의한 Shared 이벤트 계약을 통해 이 연결 지점에 전달한다.

## 확인

EditMode의 `ScreenControlStateTests`는 시작 완료 전 상태 유지, 중복 요청 차단, 정지 실패/재시도, 만료 요청의 늦은 응답, 제어기 미연결, 악기·모드 독립성을 검증한다. 실제 카메라/연주 시작과 기기별 한글 폰트·터치 입력은 통합 후 확인해야 한다.
